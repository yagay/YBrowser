## Method and limitations

The connected GitHub tool can fetch individual known paths, but repository-wide listing/code search returned no usable manifest. Direct Git clone failed (DNS resolution). No Gradle/Android SDK build or device test ran. This audit covers selected files only.

## Confirmed findings pending batch fixes

- **AUD-001 [P1, browser UI]**: `BrowserApp.kt` calls `ReaderOfflineRepository.contains()` while composing both error views. File-system IO occurs on the UI thread, and duplicated guards can be consolidated.
- **AUD-002 [P1, retained renderer]**: inactive WebView/GeckoView surfaces remain mounted at alpha 0. Touch and accessibility are partially blocked, but native Surface rendering/IME/focus isolation has not been verified on devices. Requires engine-specific instrumentation and real device validation.
- **AUD-003 [P2, offline persistence]**: `ReaderOfflineRepository.list()` parses every saved JSON (up to 500 normal snapshots) on each refresh. Although dispatched to IO, this is inefficient. An indexed metadata approach would avoid repeated full-body reads.
- **AUD-004 [P2, saved reader UI]**: asynchronous delete and refresh transitions need integration tests for dismissal, cancellation and rapid reopen.
- **AUD-005 [P2, workspace layout]**: viewport height relies on measured toolbars and delayed inset release. No verified tests cover toggling auto-hide during keyboard/fullscreen, orientation or desktop tab-strip changes.
